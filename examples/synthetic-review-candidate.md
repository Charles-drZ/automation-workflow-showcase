# Synthetic review-candidate example

This example is intentionally descriptive rather than schema-shaped. It shows the review logic without reproducing a private contract or workflow payload.

## Work-source observation

A completed validation task has matching Git evidence and is eligible for durable-memory review.

## Current durable-memory observation

No reviewed long-term summary is visible for the same topic.

## Integrity state

The selected observations are complete enough for a human review. No missing-source warning or ambiguous match is present in this synthetic example.

## Candidate reason

The evidence suggests that a bounded durable note may be useful, but the automation does not decide whether the project meaning is important enough to retain.

## Human decision

A reviewer checks accuracy, scope, duplication, privacy, and long-term value before approving or rejecting a proposal.

## Verification

After an approved change follows normal repository review, the durable target is observed again. The result is recorded only if the expected reviewed state is present.

No real project data, identifiers, contract fields, prompts, node configuration, or synchronization records are represented here.
